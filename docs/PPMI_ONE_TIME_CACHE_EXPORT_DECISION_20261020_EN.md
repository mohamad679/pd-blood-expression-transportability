# One-time export from the existing PPMI IR3 cache

**Status:** fixed before this new export is run on the real cache. This is a narrow, user-directed exception to the earlier prospective Mac-only processing plan. It does not rewrite the historical preparation record and is not the second public scoring lock.

The researcher's personal Windows computer already holds `IR3_PRIVATE_CACHE.zip`, produced during the completed archive audit. That cache contains the complete 4,871-row `metaDataIR3` release table, matching portal/age/status exports, the fixed GENCODE reference, a count-file linkage index, and cached count vectors. Re-reading or transferring the approximately 42-GB original archive is unnecessary. Run `pipeline/windows_ppmi/prepare_ppmi_remaining_inputs.py` once on this existing cache, using only the bundled, fixed code. The fixed 472-candidate bundle may also be supplied for an immediate exact-set comparison; its absence does not prevent the full-cache audit because the candidate set can be reproduced from the cached metadata and linkage index. Reconcile it with the frozen bundle on the Mac before locking the final population.

The one-time run produces three outputs in a new local directory:

1. `PPMI_COMPLETE_METADATA_AGGREGATE.json`: counts, QC cross-tabulations and rates by historical group, stage exclusions, exact-link and donor counts, input/output hashes, and reconciliation status. It contains no identifiers, individual rows, expression values, or scores; this is the only file to attach in chat.
2. `PPMI_COMPLETE_METADATA_PRIVATE.zip`: the complete release, portal, age and status source tables, cached count-file linkage index, reference-gene table, and a checksum manifest. It contains participant-level metadata. Transfer it directly to private local storage on the researcher's Mac and provide only its local path, never its contents in chat, Git or Zenodo.
3. `PPMI_ALL_VISIT_RANKS_PRIVATE.zip`: one within-sample rank vector per cached release sample, with its private metadata row and a checksum manifest. The fixed feature transformation is the same count/exon-union-length division and within-sample midrank operation used for the baseline candidate bundle. This is **feature preparation only** for the prespecified post-lock longitudinal similarity diagnostic. It performs no across-sample centering, similarity, model fit, cell-panel score, sex/age prediction, or PD prediction. Transfer it locally to the Mac, not through chat or public storage.

The Mac remains the site for final population reconciliation, the second public lock, all controls/scoring, and inference. The existing Mac baseline candidate bundle, whole-blood collection and LEDD exports, CBC exports, and frozen GEO model artifacts are separate inputs already acquired. The two new private bundles are intended to close the remaining source-cache input gap in one pass, including the nonbaseline samples needed for the longitudinal diagnostic. A source-version discrepancy or failed checksum must be reported together as a single validation failure; no PPMI score may be used to revise this extraction rule.
