# PPMI pre-QC denominator and group-specific QC audit decision

**Status:** fixed metadata-only analysis rule, before running this audit on the full release metadata. This is not the second public lock and authorizes no expression-derived scoring or model fit.

The audit was initially planned for the researcher's Mac. Under the later [one-time existing-cache export decision](PPMI_ONE_TIME_CACHE_EXPORT_DECISION_20261020_EN.md), it may also run locally on the researcher's personal Windows computer against the already cached full source metadata; final reconciliation still occurs on the Mac. Inputs are the complete IR3/B38 RNA release sample metadata (`metaDataIR3`), the matching complete portal sample export (`meta_data.11192021.csv`), baseline age export, and the existing 472-candidate selection reconstructed from the audited cache (with an optional exact comparison to the frozen candidate bundle). Only metadata and the count-file linkage index are read for the QC audit; its output contains counts and input hashes, never participant IDs, sample IDs, individual rows, or expression values. The current participant-status export is not used to relabel historical samples: historical group is determined from the portal's three agreeing fields and the release diagnosis, as in the original candidate rule.

Two nested pools must be distinguished. The **broad release pool** comprises every release row with `CLINICAL_EVENT=BL` and `DIAGNOSIS` equal to `PD` or `Control`, before `QCflagIR3` is inspected. It measures linkage coverage and cannot by itself be called the Long RNA QC denominator. The **strict linked pre-QC denominator** comprises broad-pool rows with a usable PATNO, exactly one portal row matched by the unmodified `HudAlphaID` or `Sample` value to `HudAlphaSampleName`, matching PATNO and baseline event, `Long RNA-seq=Yes`, and agreement of all three historical portal labels with the release diagnosis. None of these requirements refers to either QC flag. Release rows with no or ambiguous portal match, missing/discordant ID, nonbaseline portal visit, non-Long-RNA status, or discordant diagnosis are counted separately by release group and are never silently assigned a QC outcome.

For transparency, the broad release pool also receives a release-QC count by group. This does not replace the strict linked denominator or supply a portal-QC rate.

Within each strict denominator group, cross-tabulate release `QCflagIR3` as `pass`, `fail`, or `other/missing` against portal `QC` as `highqc`, `other`, or `missing`. Report each group denominator, explicit release-fail count and fraction, portal-not-high-QC count and fraction, any-QC-exclusion count and fraction, and unknown-QC count. A non-high-QC portal flag is an exclusion under the original rule, but is not automatically called a documented QC failure. The numerator and denominator for every fraction must be displayed. The both-QC-pass subset is then subjected to the already registered valid baseline age and matching recorded sex checks. The 472 provisional bundle samples must be an exact, unique subset of the resulting metadata-eligible samples; any missing, duplicate, or contradictory key makes reconciliation fail without emitting the key. Extra metadata-eligible rows are counted, not retrospectively removed or silently treated as final candidates; expression linkage and donor review remain separate prerequisites.

The unit is a release **sample row**, with unique-participant counts shown separately. Repeated baseline samples for one donor do not become independent donors and must be reviewed before the final population is frozen. All counts are descriptive. The group-specific denominator is not available until the complete release metadata is audited from the existing cache and reconciled with the frozen Mac candidate bundle. The tool's synthetic self-test precedes the real cache audit. Commit and push this decision and the audit implementation before the real audit.
