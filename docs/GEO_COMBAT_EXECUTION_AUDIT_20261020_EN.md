# GEO ComBat execution and numerical audit (2026-10-20)

This audit separates the metadata-only rule amendment, the interrupted first real run, and the numerical recheck. It does not change the frozen primary models or rerun the completed 39-arm-scope sensitivity.

## Small-batch rule and outcome visibility

The initial proposed rule made an entire fitting partition non-evaluable when any training batch contained fewer than three samples. The [metadata-only feasibility count](GEO_COMBAT_BATCH_FEASIBILITY_20261020_EN.md) found this would invalidate 0/5 outer and 8/25 inner PROBE partitions, and 5/5 outer and 24/25 inner GENEPARK partitions. GENEPARK's full-cohort singleton is `08/27/09_TRO`. The rule was amended to **partial ComBat**: estimate and apply correction only for batches with at least three training samples; retain small- or unseen-batch samples uncorrected in the model and report coverage. The [decision document](GEO_COMBAT_AUDIT_DECISION_20261019_EN.md) records this rule, the rank-matrix input, and the three analysis arms.

Local filesystem timestamps put the feasibility and amended-decision documents at **2026-10-20 01:01 +03:30**, and the first real-run `STARTED.json` at **01:34 +03:30**. The recorded count explicitly used sample metadata and the frozen split manifest, without expression or performance metrics. This supports that the amendment preceded all *real GEO ComBat* AUROC outputs by about 33 minutes. These decision documents were not Git-committed or externally timestamped at that time; filesystem timestamps and the recorded chronology are the available evidence, and should not be represented as an independently verified preregistration.

### Source-code identity across the interrupted run and retry

The two `STARTED.json` files are exactly equal and contain matching split, input, batch-metadata, ComBat-version and NumPy-version fields. **Neither contains a hash of the ComBat runner source.** The runner file's local modification time is **01:57:22 +03:30**, between the first start (01:34:48) and the retry start (01:58:53). The runner was edited to repair safe resume/progress handling. No preserved copy or source hash from the first start is available, so it is **not possible to establish byte-for-byte code identity between the two executions**. Nor do matching data/version hashes by themselves prove that the computational code was identical. This provenance gap must remain explicit in any methods audit.

This does **not** invalidate the fact that the three recovered first-run artifact sets are byte-identical to the copies included in the completed retry; it limits the stronger claim that all 39 arm-scopes ran with precisely the same source bytes. Before treating the ComBat sensitivity as source-uniform for a final reproducibility release, the narrow repair is to rerun the three `GSE57475/outer/0` arm-scopes using one frozen, committed runner version and compare their held-out predictions, decisions, fit records, and correction coverage against the retained first-run artifacts. This would test output equivalence; it still cannot recover the missing first-run source hash. No such replay has yet been performed.

Before the first real run, the initial **synthetic software test** failed because the pinned `neuroCombatFromTraining` path was incompatible with NumPy 2 (`TypeError` when converting a length-one array to an integer). The dedicated ComBat lock was changed to NumPy 1.26.4 and the synthetic test passed. No real GEO ComBat performance metric came from this software failure.

The **first real run** was interrupted after completing the three arms of `GSE57475/outer/0`; the next arm-scope was incomplete. The user reported that the terminal stopped responding, and the first-run directory has no recorded `FAILURE.json` or stack trace establishing an algorithmic exception. Its `PROGRESS.json` contains metrics, and the first arm-scope AUROC was inspected while diagnosing the progress display. Thus it would be false to say that *no* AUROC had been seen before the retry; those AUROCs were seen **after** the small-batch rule amendment. The first resume command then failed closed with `Cannot safely resume: completed result history is incomplete`: the initial progress file retained only the latest result row, not the full three-row history. The runner was repaired to reconstruct completion only from verified final artifact sets, with input and split hashes checked; the failed resume attempt did not produce a new analysis result. The successful retry directory reused the three complete artifact sets and completed the other 36 arm-scopes. For the three reused scopes, the first-run and retry copies of `heldout_predictions.npz`, `combat_coverage.json`, and `fits.jsonl` have matching SHA-256 hashes. The final summary reports 39/39 complete, zero `not_evaluable`, and three `recovered_after_interruption` entries. This is consistent with the amended partial-correction rule, not the original whole-partition rule.

## Numerical-warning recheck

The full-run terminal output had repeated `RuntimeWarning: divide by zero` messages from `neuroCombat`, but the original runner did not retain those stderr messages. To preserve and investigate them, [audit_geo_combat_numerics.py](../pipeline/audit_geo_combat_numerics.py) repeated **ComBat fits and transforms only**, without model refitting or outcome scoring, for the frozen `GSE99039/outer/0` scope. It used the same input hashes, split-manifest hash, batch metadata, ComBat version, and partial-correction threshold as the full run. Both inductive arms were checked at all five inner fits and the outer refit, plus the transductive full-scope fit: 13 ComBat fits and 25 adjusted train/held-out/full-scope matrices.

The diagnostic [summary](../results/geo_combat_numeric_audit_20261020/SUMMARY.json) records **zero NaN and zero Inf** values in all 25 adjusted matrices and finite numeric fitted estimates. Small/unseen-batch samples were exactly unchanged. Its captured [stderr](../results/geo_combat_numeric_audit_20261020/combat_stderr.log) contains **30 divide-by-zero RuntimeWarnings**. The pinned `neuroCombat==0.2.12` source places these at line 324, where relative changes in iterative location/scale estimates are divided by the previous estimates. The warning therefore identifies a zero denominator in the convergence-change calculation; it does **not** establish that within-batch zero-variance genes caused it. Finite returned matrices do not prove that every estimate converged to a stable solution, and this one-scope diagnostic does not certify numerical behavior in all 39 arm-scopes. The original run's unretained warnings cannot be counted retrospectively.

The numerical audit is a **matrix-finiteness pass with unresolved RuntimeWarnings**, not an unconditional numerical-validity pass. The article table is consequently an exploratory sensitivity summary with this limitation disclosed. A stronger convergence claim would require a separately specified check of the iterative solver, rather than inferring convergence from finite predictions alone.

## Model path and interpretation boundary

ComBat is applied to the within-sample gene-rank matrix before panel-score construction and MAD selection. Consequently, corrected expression changes M4's panel features as well as M5's panel and gene features; the original M1–M5 results remain untouched. The prespecified cautions in the [decision document](GEO_COMBAT_AUDIT_DECISION_20261019_EN.md) anticipated that no-disease adjustment could remove true disease-associated variation when batch and diagnosis are imbalanced, while preserving disease as a covariate could accentuate apparent group differences. The observed pattern is compatible with these cautions but does not identify how much of any AUROC change is technical versus biological. The transductive arm uses held-out expression in correction estimation and cannot be interpreted as an inductive external-validation result.
