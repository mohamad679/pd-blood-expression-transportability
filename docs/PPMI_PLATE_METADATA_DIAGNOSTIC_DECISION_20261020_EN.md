# PPMI plate metadata diagnostic: decision before calculation

**Population and input.** Use exactly the 472 provisional baseline candidates in the already audited Windows-prepared private bundle (SHA-256 `1b191f042885eedf2eea00c69ce79a269cc647ef4d5148b37b678b97c7d0333c`), with historical PD/control labels and the `Plate` field from `metaDataIR3_original`. This is a metadata-only, pre-second-lock descriptive check. Do not read individual expression values, compute panel or model scores, fit a model, or alter PPMI eligibility.

**Plate-only AUROC.** For each release plate, calculate its PD count divided by its PD-plus-control count among these same 472 candidates. Assign that prevalence to every candidate on that plate. Compare all PD–control pairs; a greater PD score contributes one, an equal score one half, and a smaller score zero. Divide by the number of PD–control pairs. This is an **in-sample descriptive AUROC**, intentionally optimistic because each candidate's label contributes to its own plate prevalence. It is not cross-validation, a theoretical ceiling, or a confirmatory PPMI result. Report the total counts, pair denominator, and the result beside the earlier GENEPARK in-sample batch-only value, with the different cohorts and batch definitions explicit. No confidence interval or significance test is planned for this descriptive check.

**Two plate fields.** Preserve release `Plate` as the reference technical variable. For this export only, canonicalize a release value matching a positive decimal integer and a portal value matching case-insensitive `p` followed by a positive decimal integer by converting the numeric part to an ordinary decimal integer string. Fail if any row does not match this syntax, the canonical values disagree within a candidate, or the observed raw release-to-portal relation is not one-to-one in both directions. Report the aggregate crosswalk and counts only. This naming check does not independently prove biological donor identity.

**Plate 201.** Retain the one provisional PD candidate on release plate `201` and portal plate `p201` in all counts and in the plate-only calculation. Record its single-candidate status. Its purpose (for example, rerun or reprocessing) is unknown unless source documentation explicitly establishes it; do not infer it from the number.
